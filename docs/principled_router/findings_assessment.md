# 这条方向能否支撑 Findings(2026-10-24 PT,初判)

**结论:能作为 Findings 的方法替换与分析部分,但还撑不起独立贡献;要成立,必须补上真实的相近领域评测,并解决 unknown 校准。预计 1–2 周 CPU + 数据工作,之后才值得上 GPU。**

已经站得住的:
1. 4 个可解释参数的音频时间 HMM 替换了约 7 个手写守卫,交叉验证下覆盖率 96.2%(线上 96.9%),平均 slice 数 1.18(线上 4),集合变化 156 次(线上 1,142)。每个参数都有平滑的 sweep 曲线,c_u 例外。这直接回应"启发式堆砌"和"墙钟计时"两条批评。
2. 有显式的 unknown 状态和可量化的拒识曲线:删掉 medicine 时 c_u=0.50 拒识 78% 的未知窗口、已知领域覆盖只降 2.4 点;线上 router 在同样设置下必然装满 4 个错误 slice。

站不住、必须补的:
1. 两领域流对路由没有区分力,静态并集就是 100%。必须有多于预算 B 的相关 slice,才能证明"路由"本身有价值。
2. 相近领域:24 个子领域 prototype 下子领域覆盖只有 64%(1.85 个 slice),肿瘤学子专科之间混淆严重。需要真实子领域术语表,才知道这在术语准确率上丢多少。可用数据:ESO 训练集 990 讲(有人工转写 SRT,许可未知,需先问数据提供方);ACL 60/60 只有 10 个 talk,子领域多样性不够,需要补公开学术讲座。
3. unknown 校准:按 slice 校准与学习版已在术语表弱监督下实现,均未优于全局阈值(`results_calibrated_20261024.md`);需要无标签真实译文做校准,与相近领域数据合并为同一个数据缺口。
4. 语言:De 的 ESO 参考是人工翻译(已核对),Ja/Zh 是模型生成。En→De 可以作为人工参考的主语言对,但 HMM 只依赖译文嵌入,换语言需要重跑 embed;de/ja 的闭环 run 目前没有 per-window 记录可供 replay。

建议的下一步顺序:(a) 实现学习版与按 slice 校准的 unknown,在同一 replay 上对比;(b) 用 ESO 训练集讲稿按子专科构造 slice 与流(先确认许可);(c) 有区分力的合成流(≥8 个相关 slice、快速切换)replay;(d) 只有当 (a)–(c) 显示与线上 / 静态基线的真实差距时,才做 En→Zh/De 闭环。
